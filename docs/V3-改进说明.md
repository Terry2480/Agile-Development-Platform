# AgileCampus v3 改进说明（相对 v2）

> 日期：2026-10-10 ｜ 基线：v2（`44db54e`，业务后端 + 深色蓝白黑工作台）
> 本分支（`proposal/dark-workspace`）当前代码为 v2；本文所述 v3 功能已在本地全部实现并通过接口与浏览器双端实测，代码可按团队决定随时推送到本分支。
> 与 v2 相同的约定不再重复：v1 登录系统完全兼容、零新增 npm 依赖、配色仍为蓝/白/黑三色。

## 改进总览

| # | 模块 | v2 | v3 |
|---|---|---|---|
| 1 | 加入团队 | 仅管理员按邮箱直接添加 | **+ 邀请码自助加入**（两种方式并存互不干扰） |
| 2 | 权限 | 仅团队级角色（owner/admin/member），全项目通用 | **+ 四级项目权限 I/II/III/IV**，仅本项目生效、互不混用 |
| 3 | 界面布局 | 任务/聊天/概览三栏固定并排 | **三页独立切换**，左侧子项点击切换单面板占满 |
| 4 | 成员视图 | 仅成员列表（头像/在线/角色） | **+ 成员项目主页**：查看单人任务全景并直接派任务 |
| 5 | 团队公告 | 聊天置顶消息（仅管理员手动置顶） | **+ 「发布公告」专属入口**（悬浮置顶、自动取代旧公告） |

## 1. 邀请码自助加入团队

- 建团队自动生成 **8 位邀请码**（大写字母+数字，剔除易混的 0/O、1/I/L，课堂口传友好；`crypto` 生成，保持零依赖），团队邀请弹窗展示并可一键复制
- 新接口 `POST /api/teams/join { inviteCode }`：任何已登录用户凭码**自助入队**，自动加入该团队全部项目；无效码 404、重复加入 409（数据库唯一约束兜底并发）
- 界面：侧栏新增「凭码加入团队」🔑 弹窗（自动大写、回车提交、成功提示）；邀请弹窗升级**双模式**——上半部邀请码（复制发同学），下半部保留邮箱直拉

## 2. 四级项目权限体系（核心改进）

**模型**：`I > II > III > IV`，存于 `project_members.permission`，**权限仅对本项目生效**——同一人在 A 项目是 I、在 B 项目可以是 IV，互不混用。

**初始权限规则**：

| 身份 | 初始权限 |
|---|---|
| 项目创建者（建立团队者建项目） | **I** |
| 建项目时就在团队内的成员 | **II** |
| 项目建立后才入队（邮箱邀请/凭码）的成员 | **IV** |

**能力规则**（集中配置于 `lib/permissions.ts`，改层级数/能力口径只动这一个文件）：

| 能力 | 谁可以 |
|---|---|
| 打开成员项目主页并直接添加任务 | I、II |
| 发布团队项目公告 | III、IV |
| 调整成员本项目权限 | I、II |

**改权限三重守卫**（接口 `PUT /api/projects/[id]/members/[userId]`）：

1. 赋予的权限**不得高于自身**（II 不能把人提成 I，同级允许）
2. **不得改动权限高于自己的成员**（II 不能动 I）
3. 项目**须始终保留至少一名 I**（防止降掉唯一管理者后无人治理）

界面联动：概览页权限下拉**按自身等级过滤可选项**（II 只见 II/III/IV）；权限比自己高的成员只显示只读徽章。

## 3. 三页独立切换布局

「项目任务 / 团队聊天 / 项目概览」从三栏并排改为**由左侧项目子项（或顶栏菜单）切换的独立整页**：

- **项目任务页**：原任务面板（分组/筛选/Tab/新建）不变
- **团队聊天页**：全宽消息流（阅读体验显著提升）+ 置顶公告悬浮栏 + 发布公告按钮
- **项目概览页**：双列网格——左列迭代进度卡（Sprint 名/交付倒计时/进度条/三格统计）+ 团队成员（在线状态/项目权限/可点入主页），右列项目日志时间线 + 项目文件库

切换页面时自动退出成员主页视图；通知、待办两个独立视图不受影响。

## 4. 成员项目主页（新页面）

I、II 权限者在概览页**点击成员**进入：

- 头部：头像 + 权限徽章 + 在线状态 + 本项目任务统计（共 N · 已完成 M）+ 邮箱
- 主体：该成员在本项目的任务按 进行中/待开始/已完成 分组
- 「＋ 添加任务给 TA」：新建任务弹窗**负责人自动预选**该成员，创建后立即出现在其主页与项目列表

## 5. 团队项目公告

- 聊天页新增「📢 发布公告」按钮（仅项目权限 III、IV 可见）→ 弹窗输入（≤300 字）
- 公告 = 频道内置顶消息，以**悬浮置顶栏**常显于聊天顶部，新公告自动取代旧公告（公告位唯一）
- 发布动作写入项目日志，全员可在日志中追溯

## 接口与数据结构变化

**新增接口（3 个）**：

```
POST /api/teams/join                              { inviteCode } → 凭码入队
PUT  /api/projects/[id]/members/[userId]          { permission } → 调整项目权限（三重守卫）
POST /api/projects/[id]/announce                  { content }    → 发布公告（=置顶消息）
```

**返回结构变化**：

- `GET /api/teams`：+ `inviteCode`
- `GET /api/projects/[id]`：+ `myPermission`、`members[].permission`、`team.inviteCode`

**数据表变化（2 列）**：

- `teams.invite_code`：text，NOT NULL UNIQUE（存量团队已回填）
- `project_members.permission`：text，NOT NULL DEFAULT 'IV'（存量成员按初始规则对齐）

完整接口文档见 `docs/API.md`（已同步更新权限规则与新接口）。

## 实测记录（全部通过）

- 邀请码：无效码 404 / 重复 409 / 跨账号凭码入队成功并自动进项目
- 初始权限：建项目（创建者 I、在场成员 II）、邮箱邀请后入者 IV
- 守卫：IV 改权限 403；II 赋 I 403；II 动 I 403；II 降同级→IV 200；唯一 I 自降 400
- 公告：IV 发布成功置顶、I 被拒 403；公告自动取代旧置顶
- 成员主页：I 点开成员 → 派任务（负责人预选）→ 任务落库并出现在主页
- 三页切换：子项/顶栏切换正常，成员主页退出逻辑正确
