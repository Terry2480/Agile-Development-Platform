# 聊天时间修复

聊天时间改为 PostgreSQL timestamptz，浏览器显示与日期分组统一使用 UTC+8。不要对全部消息直接减八小时：旧数据库可能按 UTC 或北京时间保存，必须先确认。

服务器维护前备份数据库，停止应用，更新代码和依赖，然后执行只读检查：

```bash
npm run db:fix-chat-timezone -- --check
```

检查输出的数据库时区、字段类型和最近消息原始时间。将原始时间与一条已知消息的实际发送时间比较。例如原始记录是 10 月 13 日 17:26，实际也是北京时间 17:26，历史时区应指定 Asia/Shanghai；若原始记录是 09:26，实际北京时间 17:26，应指定 UTC。

确认历史记录保存的是北京时间时运行：

```bash
LEGACY_CHAT_TIMEZONE=Asia/Shanghai npm run db:fix-chat-timezone
```

确认历史记录保存的是 UTC 时运行：

```bash
LEGACY_CHAT_TIMEZONE=UTC npm run db:fix-chat-timezone
```

选择其中一种，不能先后执行两种来试错。脚本在事务中转换历史时间及默认值；已是带时区类型时会跳过，未指定历史时区时拒绝转换。若历史上调整过数据库时区，记录可能混用时区，需要逐批核对后处理，不能统一转换。

完成后重新构建、启动应用，检查已知消息和新发送消息的日期、时间与跨午夜分组。仅设置服务器 TZ 或只更新前端，不能修正此前已误解的历史时间。
