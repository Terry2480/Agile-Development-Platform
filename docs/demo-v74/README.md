# v7.4 课程演示数据

本目录是可移交的合成数据包。在准备好的独立演示实例中通过浏览器录入。演示数据.json 是录入清单，系统无需提供 JSON 导入功能。Day 0 取实际准备日期，其他日期按自然日顺延。可在课堂场景完成后将任务状态恢复到清单所列状态。逐步的界面点击路径见 [v7.4 演示部署与验收手册](../v74-demo-deployment.md#11-阶段-j--浏览器录入演示数据约-3045-分钟)。

1. 按清单注册负责人和成员：注册页字段是「学工号」「邮箱」「密码」（密码至少 6 位），没有姓名字段，注册后到「设置」→「名称」改成林青禾 / 陈星野。各自设置独立密码；账号已有时使用已有账号，避免重复创建。密码单独保存。
2. 负责人创建团队，让成员加入（团队「管理成员」→「邀请成员」填成员注册邮箱即可，无需对方确认）。创建课程项目和迭代，将三个任务分配给清单中的负责人，设置状态、截止日和优先级。任务新建弹窗没有状态字段，建完在任务详情里改；任务编号取系统实际分配值。
3. 新建“报名流程课堂验收”，关联三个任务。首次展示应有一项完成、一项进行中、一项待开始，里程碑关联任务进度为 1/3。
4. 项目文档中在根层「＋ 新建分区」建立“课堂交付”，进入该分区后「＋ 新建 → 在线文档」新建“活动报名与名额规则”，把同名 Markdown 文件中的标题、规则和说明录入正文，点「立即保存」再「保存并结束编辑」。
5. 成员打开“验证报名确认与重复提交”，从关联资料区「上传并关联」上传同目录的 TXT 附件一次，目标目录选“课堂交付”（根层不能上传，必须先进入该分区）。负责人在里程碑的「关联资料」→「关联已有资料」中选择已上传的附件及在线文档。
6. 分别以两个账号打开项目。成员应能在自己的待办中找到进行中的任务。从任务和里程碑分别下载附件，核对两次下载的文件 SHA-256 与源文件一致。Windows 用 Get-FileHash，Linux 用 sha256sum。刷新页面后重新打开在线文档，核对三条报名规则。
7. 再次准备同一演示时，按团队、项目和标题复用已有条目，只补缺项。记录实际账号、项目编号、验收结果及异常至部署记录，口令不要写入仓库。
