# 文档系统：部署、迁移与恢复说明

编写日期：2026-11-15。本轮仅在本机隔离库实施；本文件不表示已经生产发布或生产恢复演练通过。功能验收入口见 [验收指南](document-system-acceptance.md)。

## 环境要求

应用以长期运行的 Node 服务启动，挂载持久 PostgreSQL 与文件目录。不能使用请求结束就回收、没有持久本地磁盘的运行方式承载当前后台导出/清理实现。多个进程共享同一数据库和文件根目录，队列通过数据库锁与租约协调；每个实例的浏览器/字体环境须一致。

- `DATABASE_URL`：目标数据库连接串；迁移命令另外要求明确的数据库名确认。
- `UPLOAD_DIR`：普通开发默认仓库 `uploads`，审查脚本固定 `uploads-document-review`；生产设置绝对持久目录，沿用旧附件目录或先完整迁移目录。更换根目录而不搬文件会造成文件缺失。
- `DOCUMENT_BROWSER_PATH`：可启动的 Edge/Chromium 完整路径。Windows 默认寻找 Edge；Linux 默认尝试 Chromium/Chrome。`playwright-core` 不自动下载浏览器。
- 中文字体：Windows 的 Microsoft YaHei 或 Linux 的 Noto Sans CJK SC 等；PDF 必须在目标机验证中文、表格、图片。
- `AUTH_ALLOWED_ORIGINS`：实际页面准确的协议、域名与端口，遵循已有认证部署说明；不以通配符或关闭来源校验处理问题。
- 服务账号应能读写文件根目录、其 `.document-exports` 子目录，且能启动无头浏览器。PDF 生成依赖系统浏览器运行库；不要为解决权限问题随意关闭沙箱或提升服务权限。

导出当前串行消费任务，缓冲生成的 PDF/Markdown 内容，并限制未压缩总量 500MiB。建议目标服务至少预留 2GiB 可用内存并监控磁盘，实际并发和容量在目标机测量；本次没有做 500MiB 实际满载压力验证。通用上传上限 100MiB，代理/反向代理也须允许相应请求（另有 multipart 开销），不能只调整前端。

## 安全升级顺序

1. 集成并固定完整验收提交，运行 lint、类型检查、构建及隔离测试，完成组员验收。检查 `package-lock.json` 和全部迁移都在提交中。
2. 记录旧附件 ID、`stored_name`、大小、任务/里程碑关联；导出 PostgreSQL 一致性备份，并备份同一时点的文件根目录。**数据库备份不能代替文件备份。** 在另一隔离库和目录恢复并核对，不能用 seed 覆盖真实数据。
3. 先部署能识别新资源的兼容清理代码；旧清理遇到已纳管文件会转交引用感知队列，避免副本/历史仍用时误删。数据库旧写保护触发器阻止直接删除已映射附件。
4. 明确停用旧写入口的窗口。用目标连接环境运行下列命令，`目标数据库名` 必须与连接串一致，命令不负责自动挑选生产库：

   ```powershell
   npm run db:add-documents -- --database=目标数据库名 --backfill
   # 核对迁移、附件映射及存储实际可读性后，在维护窗口切换：
   npm run db:add-documents -- --database=目标数据库名 --backfill --cutover
   ```

5. 初次 backfill 有固定边界，审查期间后来的旧附件不会偷偷进入已完成的初迁移。`--cutover` 在事务内锁住旧写相关表，补迁移边界之后未映射的附件/链接，再登记 `documents-api-cutover-v1`；切换失败全事务回滚。保留旧 URL 映射和旧附件元数据，不复制二进制。不要在切换后继续运行旧版本应用写入附件。
6. 验证 `document_migrations` 中 schema、模板、导出元数据、操作日志、backfill 与 cutover 记录。检查 `/api/document-status` 已认证响应 `enabled:true`；用两角色验证目录、旧下载、任务/里程碑入口、替换、图片和导出。该接口只表示当前库切换状态，不代表某个外部环境也切换。
7. 恢复服务并观察后台：导出约每 5 秒消费，回收/资源清理和旧附件队列约每 60 秒运行；服务关闭期间不会执行，到期访问仍按数据库时间拒绝。检查队列错误、失败次数、导出失败清单，不把日志“稍后重试”当成清理完成。

001/002 是已安装基线，003 模板推荐、004 导出快照元数据、005 文件/链接操作日志为独立增量。已安装迁移校验和不允许修改；生成脚本已冻结 001，后续改结构新增编号迁移。`.gitattributes` 对迁移 SQL 禁用 Git 换行转换，跨平台保留原始字节；不要格式化已安装 SQL 或修改其换行。不要通过 `db:push` 或重生成 001 绕过一致性检查。

## 后台保留与监测

| 对象 | 保留/清理行为 | 核对重点 |
| --- | --- | --- |
| 回收站 | 删除起 30 天；恢复再删除重新起算；项目转存不重置 | 到期不可读/恢复，后台逻辑永久清理，归档项目也可到期清理 |
| 内部未引用图片 | 24 小时宽限；有效编辑锁/授权继续保护 | 当前正文、历史、副本、导出任一引用存在则保留 |
| 历史 | 每文档最多 10 份附加快照 | 淘汰后仅对不再被任何对象使用的资源排清理 |
| 导出 | 快照起 24 小时，重试不延长 | 到期禁止下载、释放快照引用并删除产物；任务删除或进程崩溃遗留的自有 UUID 产物超过 24 小时后扫描清理，不扫描删除未知普通文件 |
| 幂等请求 | 完成记录 24 小时后分批清理 | 同键不同内容在有效记录内冲突；成功响应丢失可安全重试 |
| 团队解散后的实体 | FK 无关的旧清理队列保存文件名，失败可重试 | 不把队列入站误报为磁盘即时删除；导出下载入口立即失效 |

项目删除要转存正常/回收内容、历史、图片和旧 URL 身份，不能直接 SQL 删除项目。团队必须先处理全部项目，再由负责人明确确认公共区永久删除；有效编辑阻止删除，活动导出不阻止，但被取消。所有生命周期操作走应用事务。

## 故障与恢复

- 迁移失败：保留错误码，确认事务回滚及原映射数量；排查缺失引用、非法旧链接、校验和或磁盘缺失后重跑同命令，不手动伪造成功标记。
- 旧文件下载失败：核对当前 `UPLOAD_DIR`、资源 `stored_name` 与实体大小；找回原文件或一致性备份，不能把缺失文件标成导出完整成功。
- 导出部分失败：按任务失败清单修复实体/运行环境后重试原快照；超过 24 小时或来源已不可读时重新发起。PDF 浏览器/字体问题先修目标环境。
- 清理失败：保持队列记录，修正磁盘权限/占用后让服务重试。禁止直接扫描删除所有“看起来未用”的文件。
- 回退：切换前可停止新写、检查旧元数据后撤回应用版本；**切换后已有新正文/替换/转存时，不能只回退旧应用或删 cutover 标记**。应停止写入与清理，按同一时点同时恢复数据库和文件备份到隔离环境，核对数量、下载、历史、关联，再决定恢复服务。否则会丢新数据或让旧清理误删共享资源。

发布记录需填写目标提交号、备份位置、数据库/文件根目录、迁移结果、恢复演练结果、执行人和时间。本轮这些生产栏位均未执行，不能复用本机测试“通过”代签。
