# 附件一致性与部署

第二版部署时先执行 `npm run db:add-file-cleanup`，再启动应用。
更新新增清理队列表和附件删除触发器，不删除现有文件。
触发器不是 Drizzle 自动推送的内容，服务器必须运行此更新脚本。

上传前登记文件清理记录，文件写入后在同一个事务中保存附件、项目日志并移除清理记录。
数据库事务失败时立即尝试清理，暂时失败会保留记录。
进程在上传途中崩溃的文件，默认一小时后进入清理处理；文件仍有附件记录时不会删除。

数据库删除附件（含项目、团队、任务级联删除）时，触发器在同一事务中登记待清理文件。
事务回滚也会撤销清理记录，保留原文件。清理成功或文件已不存在时移除队列记录。
磁盘清理失败时记录错误类型和尝试次数，一分钟后重试。

常驻 Node.js 服务启动时及每分钟处理最多 50 个文件。多进程用数据库行锁避免同时处理同一条记录。
此后台机制适用于当前服务器常驻部署；无服务器部署应使用独立的定时清理任务。
多个应用实例必须共享同一 uploads 目录。应用需有该目录的写入和删除权限。

可查询 `file_cleanup` 的 attempts、last_error 和 not_before 检查持续失败的任务。
过去已丢失数据库记录的孤立文件没有可追踪记录，此次更新不会扫描并删除历史孤立文件。
仍需分别备份数据库和 uploads 目录。
