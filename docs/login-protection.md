# 第二版登录保护配置

本地 `npm run dev` 默认允许 localhost 同源请求，Cookie 不加 Secure。
生产环境必须使用 HTTPS；不要通过生产 HTTP 地址测试登录。

部署前，在服务器环境文件设置：

```dotenv
AUTH_ALLOWED_ORIGINS=https://你的实际域名
TRUST_PROXY_IP=false
```

可信地址必须包含协议和端口（如有），不要包含路径或末尾斜杠。多个地址用逗号分隔。
生产环境遗漏或错误配置时，修改数据请求返回 503；不可信或缺少来源的请求返回 403。
浏览器请求自动携带 Origin；手工调用接口时请提供正确的 Origin 请求头。

执行 `npm run db:add-auth-protection` 创建限流表，再构建、启动应用。
这是新增表，不修改现有账号数据。不需要修改已有密码或重新注册。

## 反向代理

仅当反向代理覆盖 X-Real-IP，而且应用端口无法被公网直接访问时，才设置
`TRUST_PROXY_IP=true`。例如 Nginx 中：

```nginx
proxy_set_header X-Real-IP $remote_addr;
```

默认不信任客户端提供的 IP 请求头；无法确定来源的请求共用一个限流桶。
未启用代理 IP 时，多名用户会共享来源限流，需要在对外测试前正确配置代理。

## 限流规则

- 登录：每个账号 15 分钟最多 10 次尝试，每个来源 15 分钟最多 100 次。
- 注册：每个来源 1 小时最多 20 次尝试。
- 邀请码申请：每个登录用户 10 分钟最多 10 次尝试。

计数存储在 PostgreSQL，用原子更新支持多实例；键为 SHA-256 摘要。
超过限制返回 429 和 Retry-After（等待秒数）。计数包含成功与失败请求，不永久锁定账号。
限流存储不可用时，登录/注册不会绕过限制。

## 检查

使用实际 HTTPS 地址测试登录、退出、上传、保存和邀请码申请。
确认响应 Cookie 包含 HttpOnly、SameSite=Lax、Secure；普通 GET 查询不受来源校验影响。
检查跨站 POST 被拒绝，反复登录返回 429，等待窗口结束后恢复。
服务器仍保留第一版时，本地改动不会改变服务器行为。
