# 站内通知与截止提醒

截止提醒针对未完成、未归档项目中的任务，发送给仍属于该团队的负责人和协作成员。按 UTC+8 的教学日期计算：截止前一天提醒一次；当天创建任务或服务恢复时，未提醒过的任务补发今天截止提醒。已过期任务不补发本轮临近截止提醒。

后台启动时检查，随后每分钟检查；通知列表读取也能触发检查，同一进程内至少间隔一分钟。生产需要常驻 Node.js 服务；无需有人打开页面，提醒会写入数据库，用户登录后可查看。

`task_deadline_reminders` 以任务、收件人和截止日期为唯一键。去重记录与通知通过同一条 SQL 原子写入，多进程重复检查不会重复发出。删除通知保留去重记录；截止日期改到另一天后可以收到针对新日期的一次提醒。负责人同时属于协作成员时也只收到一条。

通知中心与顶部通知浮层均有“删除已读”。后端只删除当前用户已读的记录，包含列表之外的较早记录；未读和其他用户的通知不会被删除。该操作不会删除任务或撤销任务分配。

点击通知会打开关联内容并标记已读：任务分配、评论、任务提及及截止提醒先切换到所属项目，再打开任务详情；项目聊天提及进入对应项目聊天。现有聊天通知没有保存具体消息 ID，因此只进入频道，不定位到某条消息。内容已删除或失去访问权限时显示提示；标记已读失败不会阻止打开内容。旧通知缺少关联信息时可标记已读，但提示没有可打开的内容。

实现参考 Focalboard 通知服务的持久化通知状态、发送前权限检查和多实例竞争处理方式，根据本项目 PostgreSQL 与 Next.js 架构独立实现，没有引入其服务或复制源代码：

- [Focalboard 通知服务源码](https://github.com/mattermost-community/focalboard/blob/main/server/services/notify/notifysubscriptions/notifier.go)
- [Memos 通知删除 API](https://usememos.com/docs/api/latest/userservice/DeleteUserNotification)
