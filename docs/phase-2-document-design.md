## 已共同核对的数据结构成果

| 结构 | 职责 | 关系及关键结论 |
| --- | --- | --- |
| document_spaces | 团队公共/项目文档空间 | 每项目一个空间、每团队一个公共区，归属及状态独立明确 |
| document_nodes | 目录及资料身份 | 文件夹与三类资料共用节点，记录名称/父级/空间；任务引用稳定 ID，不随移动改名失效 |
| document_bodies | 当前在线正文 | 结构化正文、格式版本、正文修订号、内容 hash，图片仅存资源 ID |
| document_file_entries | 上传文件资料的当前文件 | 节点连接底层资源，替换切换连接，不改变资料身份或其他副本 |
| document_resources | 实际文件记录 | 存储位置、大小、类型和上传人；内容不可变，同团队内可共用 |
| document_link_entries | 外部链接内容 | URL 独立于节点元数据，更新后关联入口跟随新网址 |
| document_resource_refs | 底层资源的使用者 | 文件条目、正文、历史、导出均计入，不把条目与正文误作两类互斥资源 |
| document_versions | 可恢复正文快照 | 正文及图片引用、生成原因和作者，当前正文之外最多 10 份；不回退目录/标题/业务关联 |
| document_edit_locks | 编辑会话独占权 | 绑定窗口会话而非只绑定用户，20 秒续期、2 分钟失效，保存另校验正文版本 |

```text
空间 → 目录节点
          ├─ 在线文档 → 当前正文 → 图片资源
          ├─ 上传文件条目 ──────→ 文件资源
          └─ 外部链接 → URL
正文历史 / 导出快照 ───────────→ 资源
资源引用表记录以上全部使用关系，供鉴权上下文及清理检查
```

用户确认上述分离思路合理，并委托助手完成余下底层设计；业务关联、删除批次、导出任务、幂等请求、旧地址映射和维护队列已纳入技术设计基线。当前结构及服务已落地，实际验证见交付记录；设计确认不替代未执行的性能或人工验收。

其中“目录里的独立文件资料”需要 file_entries；正文内部图片不需要新建该条目。两者都建立资源引用，同一底层图片可同时用于两种场景，不重复存储。条目当前资源、正文内容和引用集合须同事务维护，避免双重真相导致误删。

## 后续协作边界

用户优先核对页面入口、信息架构和操作流程；底层字段、表和 API 由助手维护，不再逐项访谈。后续出现实质数据结构调整时再集中查看，影响产品范围或权限时明确提交决定，不默默更改已确认规则。

下一主题：项目文档入口、团队公共资料入口、文档浏览/编辑区域布局。以下仍完整保留 Q1—47 的确认记录。

## 决策 01：单一位置与多处引用

用户已确认：每份资料只有一个实际目录位置，可以由多个任务和里程碑引用。关联不重复保存正文或附件实体。

- 原资料修改标题或正文，引用入口读取更新后的资料。
- 同空间目录移动保持资料身份及关联不变。
- 解除任务/里程碑关联只删除引用，不删除资料。
- 复制创建独立资料身份，后续修改互不影响。
- 跨空间移动仍遵守需求基线：先解除任务/里程碑关联；跨团队移动禁止。

复制后的二进制资源共享、正文图片的引用及回收策略尚待后续设计；独立资料身份不直接等于复制所有底层文件。不得将本决策理解成全系统文件去重已经实现。

## 决策 02：任务与里程碑的关联范围

用户已确认：任务和里程碑可以关联本项目资料及同团队公共区资料，不能直接关联其他项目的资料，也不能跨团队关联。

- 团队公共区同一份资料可以被多个项目引用，不产生重复正文或附件实体。
- 其他项目资料需要共用时，先按规则转入团队公共区；跨空间移动前必须解除已有任务/里程碑关联。
- 服务端校验资料所属空间与目标任务/里程碑的团队、项目关系，不能仅校验用户有权访问双方。
- 从公共区关联资料不产生独立副本，不扩大资料本身的访问权限。

## 决策 03：同级名称与冲突处理

用户已确认：同一目录内，文件夹、在线文档、上传文件及外部链接统一检查显示名称，不允许重名；不同目录允许重名。名称比较忽略首尾空格及英文字母大小写。

- 新建、重命名、移动遇到冲突时返回明确错误，要求用户改名，不覆盖已有条目。
- 复制自动追加“副本”，仍冲突时追加序号。
- 回收站恢复遇到名称冲突，自动追加“恢复”和序号，并展示最终名称。
- 并发操作也必须保证名称规则，不能仅依赖前端检查；具体数据库约束和序号格式在接口设计时落定。

## 决策 04：恢复位置

用户已确认：原父目录仍正常存在时恢复原位置；原父目录在回收站或已永久删除时，恢复到原空间的“恢复的资料”文件夹，并提示实际位置，不自动恢复祖先目录。

- 整体恢复文件夹保留内部结构，并沿用同级重名处理规则。
- 原空间归档或删除时不静默跨空间恢复，提示先处理空间状态。
- “恢复的资料”目录的身份、被重命名/删除或名称被占用后的处理，以及项目删除转存与回收站关系，仍需细化，不能仅按显示名称认定系统目录。

## 决策 05：复制与底层资源

用户已确认：系统内关联与移动不复制文件；主动复制资料产生独立资料身份。在线文档复制当前正文，不复制历史版本；两份正文后续独立修改，已有图片共用底层资源。上传文件复制生成独立条目，共用底层二进制内容；外部链接复制标题和网址并独立修改。

- 删除、重命名或移动一份资料不影响另一份。
- 共用资源只限既定的同团队空间范围，不引入跨团队复制或全局文件去重承诺。
- 当前正文、历史、回收站及其他有效引用均须纳入清理判断，不能因一个条目删除而破坏另一个条目。
- 资源共用不授予访问权限，图片/下载须通过有效资料上下文鉴权；不能以永久公开文件地址绕过权限。
- 新上传内容生成新资源，不能原地覆盖影响其他副本；替换操作按后续决策 20—21 执行。
- 下载/导出生成交付副本，与系统内资料身份及引用分开。

## 决策 06：文件夹整体复制

用户已确认支持按所提规则整体复制文件夹：包含全部子目录和资料，保留内部结构，在线文档仅复制当前已保存正文；不复制历史、回收站内容和原任务/里程碑关联。

- 目标仅限同团队空间，不允许复制到自身或自身子目录。
- 包含正在编辑的文档时阻止整次复制，并指出相关文档。
- 任一条目失败则整次复制失败，不留下部分目录；底层文件引用仍按决策 05 处理。
- 并发新增、修改和锁获取时的一致性方案在事务/API 设计中落实，不能只做前端预检查。

## 决策 07：分区与目录层级

用户已确认：分区是空间顶层文件夹，与普通文件夹共用目录规则。项目空间创建时提供“项目文档”“协作记录”“交付成果”三个默认分区；团队公共区按后续已确认调整采用“团队规范”“共享参考”“公共素材”。

- 分区允许新增、重命名、删除；名称不绑定权限或业务功能。
- 空间根层只放分区；资料直接存于分区内或其子文件夹，不直接放空间根层。
- 默认分区不强制保留，但空间至少保留一个正常分区，删除时需服务端并发校验。
- 删除分区同样遵守非空提示、编辑锁、引用保护及回收站规则。
- “历史文件”“恢复的资料”等特殊目录与顶层分区的身份和位置需后续确定。

## 决策 08：恢复分区的身份与管理

用户已确认：首次需要时在原空间顶层创建“恢复的资料”分区，用内部标识识别。用户可重命名，之后仍恢复至同一分区；恢复后展示实际位置。

- 可以按普通分区规则删除；其进入回收站后，下次需要时新建恢复分区，不自动恢复旧分区。
- 同级名称被占用时追加序号，不接管用户同名目录。
- 仍遵守至少一个正常分区、权限与空间归档限制；创建/恢复时服务端处理并发，不能产生多个当前恢复目标。

## 决策 09：旧附件纳入历史文件

用户在明确“历史文件”指第二阶段上线前已有附件后确认采用：升级时在各项目空间创建“历史文件”分区，将已有项目文件和任务附件纳入目录条目，不重复保存文件，保留原下载地址及任务/里程碑关联。

- 迁移后按普通分区管理，可重命名及整理；移动不改变引用，删除仍受引用保护等规则约束。
- 新上传文件不自动放入历史文件，进入用户选择的目录；任务入口上传的目录选择交互在下一项细化。
- 迁移重复运行不重复建条目，不将已整理内容移回历史文件；迁移范围应采用明确的升级边界，不能每次把新增附件重新当作旧附件处理。
- “全部文件”视图仅为讨论中的新增建议，未作为本项已确认功能；不得据此扩大实施范围。

## 决策 10：任务入口上传

用户已确认：从任务详情上传附件前选择本项目内的目录，成功后自动关联当前任务。

- 首次必须选择目录；同一任务本次操作期间可记住上次选择，用户可更改，不承诺跨设备或永久记忆。
- 目录选择器展示分区、子文件夹，允许创建目录；上传目标须服务端重新校验可写及项目归属。
- 任务入口上传仅选本项目目录；团队公共资料通过关联已有资料使用。
- 文件保存、目录条目及任务关联作为完整业务操作：失败可重试，不留下未关联的半成品。数据库事务与实体文件失败补偿的具体方法在实现契约中确定。

## 决策 11：统一关联入口

用户明确确认按 Q11 全部内容执行：任务和里程碑统一提供“关联已有资料”入口，覆盖在线文档、上传文件、外部链接。范围沿用决策 02。

- 支持目录浏览、标题搜索和多选；已关联项标记，不重复添加。
- 点击打开原资料；解除关联只移除引用，不删除内容。
- 回收站资料不可选。
- 归档项目禁止新增和解除关联，既有资料仍按当前权限查看。
- 复用选择器及公共关联规则；后端独立校验身份、范围、回收状态和项目归档状态，不能依赖选择器限制。

## 决策 12：编辑锁与项目归档/删除互斥

用户已确认：项目内存在有效在线文档编辑锁时阻止项目归档和删除，列出相关文档及编辑者；等待保存退出或异常离线后锁超时，不强制抢锁或代替保存。

- 执行归档/删除前后端再次校验，采用与编辑锁获取互斥的服务端原子机制，操作期间拒绝新的编辑锁，防止检查与写入竞态。
- 归档/删除的资料转存与失败恢复仍须保证完整性，不允许部分成功后静默结束。
- 只检查本项目内文档；引用的团队公共文档被编辑不阻止本项目归档/删除，不解除或改变公共文档的编辑锁。

## 决策 13：编辑锁续期与失效

用户已确认定期续期机制：编辑期间每 20 秒向服务器续期，距最后一次成功续期超过 2 分钟锁失效，其他编辑会话可获取。

- 页面后台仍尝试续期；浏览器休眠/节流可能导致失锁，返回前台先检查有效性，不直接继续保存。
- 正常退出先保存，成功后释放；保存失败保留本机草稿并提示，不宣称正文已保存。
- 失锁停止自动保存并保留草稿，重新获取锁且核对服务器最新内容后才能继续。
- 无强制抢锁。锁有效性以服务端时间判断，过期即不可写，不依赖后台清理及时执行。
- 续期/保存必须校验具体编辑会话的锁标识；过期续期不能复活被其他会话取得的锁。同账号双窗口仍独占。

## 决策 14：自动保存节奏与反馈

用户已确认：正文停止输入 2 秒触发自动保存，持续输入期间最多间隔 15 秒保存一次；仅正文有变化且锁有效时写入，同一文档保存请求串行。

- 显示未保存、保存中、已保存、保存失败，只有收到服务端成功确认才显示已保存。
- 保存失败保留本机文字草稿；恢复网络先校验锁与服务器版本，再重试，不盲目覆盖。
- “立即保存”只保存当前正文；“保存版本”单独生成历史恢复点，两者不混淆。
- 离开时未保存内容提示等待保存或保留草稿离开，不静默丢弃；异常关闭依赖已有本机草稿，不能承诺关闭时异步请求一定成功。
- 具体草稿落盘实现应使未触发服务端保存的文字也可恢复，退出登录清除；图片上传失败仍需重新选择。

## 决策 15：草稿冲突与人工恢复

用户已确认：本机草稿与服务器最新正文冲突时不自动合并或覆盖，先显示服务器最新正文，提供查看、复制、放弃草稿。

- 使用草稿继续编辑前获取有效编辑锁；服务器自草稿基线后已更新时，展示两份内容供比较，用户明确确认后才载入草稿。
- 草稿覆盖保存前保护服务器当前正文为历史恢复点，并遵守历史去重及最近 10 份上限；保存仍需锁与并发版本校验。
- 无访问权限不上传草稿，只提供本机文字复制出口；退出登录清除本机草稿。
- 比较不是自动合并；加载、确认后发生的服务器变化仍须拒绝过期写入，不能因用户点过确认而绕过校验。

## 决策 16：历史恢复范围

用户已确认：历史恢复仅恢复正文及其图片引用，不回退标题、目录、任务/里程碑关联。

- 历史列表显示版本时间、修改人及生成原因，包括开始编辑前、定时恢复点、手动保存等。操作人和正文原修改人的字段语义在契约中区分，避免归因错误。
- 恢复前保留当前正文，再将所选旧正文保存为新的当前内容；保持当前标题、位置和关联。
- 所选正文与当前正文相同则提示无需恢复，不生成重复版本。
- 历史引用图片需仍可用，恢复操作须持有效锁并通过并发版本校验。

## 决策 17：历史数量、去重与计时

用户已确认：当前正文不计入上限，额外保留最近 10 份历史正文。

- 开始编辑前保护服务器当前正文，与最近一份历史相同时不重复记录。
- 编辑期间每 10 分钟检查，已成功保存正文相对最近历史有变化才生成恢复点，不将未保存草稿当作服务器历史。
- 手动“保存版本”先确保正文保存成功，再立即记录；与最近历史相同提示该内容已有版本。
- 手动保存版本后下一次定时检查从此时重新计时；刷新与失锁后的计时持久化细节在服务端契约中明确，不能让客户端任意伪造历史时点。
- 超过 10 份时删除最早历史记录；图片仅在没有当前正文、其他历史、回收站等有效引用后才可清理。
- 历史恢复及草稿覆盖仍先保护当前正文，并遵守同一去重与上限规则。

## 决策 18：成员离队与编辑权撤销

用户已确认：成员关系变更生效后，服务端拒绝该用户读取正文、保存、续期、图片读取和下载；使该用户对应团队的编辑锁失效，无需等待两分钟。

- 成员变更与编辑/保存须由服务端原子校验及互斥机制处理，不能仅清前端状态。
- 页面在下一次请求发现失权后停止保存并退出服务器内容展示，提示权限变化；不承诺实时推送或撤回已到达客户端的内容。
- 未保存文字可通过本机草稿复制，不上传；退出登录清除。
- 已看到或下载到本机的内容无法收回。失去一个团队的权限不影响用户在其他团队的有效身份与锁。

## 决策 19：归档项目引用公共资料的版本

用户已确认：归档项目引用的团队公共资料仍显示最新内容，关联始终指向原资料。项目归档只限制项目自身资料，不冻结公共区。

- 不自动复制公共资料或生成归档快照。
- 团队公共资料后续更新对所有引用入口可见。
- 如需保留交付时固定内容，可在归档前导出保存；本规则不增加自动归档快照功能。
- 归档项目本身仍不能新增或解除关联。公共资料的引用删除保护仍按既定规则执行，不因来源项目归档而忽略引用。

## 决策 20：上传文件替换

用户确认首批加入“替换文件”：保留资料身份、标题、目录、任务/里程碑关联，切换为新上传内容，不提供旧二进制版本历史。

- 上传成功后原子切换资源引用；失败原文件仍可用，不原地覆盖共享二进制。
- 展示影响范围并确认：关联入口看到新内容；之前复制形成的独立条目仍引用原资源，不随替换改变。
- 旧资源仅在其他副本等所有有效引用消失后清理。
- 受权限和项目归档限制；具体替换权限在下一项明确，不沿用未经确认的权限假设。
- 本条是用户明确确认的首批范围补充，需在需求基线同步记录。

## 决策 21：文件替换权限与并发

用户确认所有当前团队成员均可替换上传文件，不限原上传者；替换前提示引用影响并二次确认，记录本次上传人、替换时间和操作日志。

- 同条目并发替换必须验证资源/条目版本，只接受基于最新版本的操作，冲突时明确提示，不静默覆盖。
- 归档项目禁止替换，跨团队及离队用户无权限。
- 历史上传者、当前资源上传者和最近修改者须区分，不能用替换后的字段错误改写已有日志归因。

## 决策 22：项目删除与回收站转存

用户已确认：删除项目时正常目录及资料转入团队公共区“原项目名称＋删除日期”归档分区；回收站资料同时转入公共区回收站，保留原删除时间和剩余保留期限，不重新计算 30 天。

- 恢复时优先放回转存后的对应目录；目录不存在时使用公共区恢复分区。
- 删除前分别展示正常资料与回收站资料数量。
- 转存失败则项目删除失败，不留下部分资料；转存与编辑锁/回收站到期清理之间需服务端互斥和事务保护。
- 资料身份及历史、底层资源引用保持，任务/里程碑关联按项目删除专门流程解除；转存后的公共区访问权限沿用团队权限。

## 决策 23：正文图片内部资源

用户已确认：编辑器上传或粘贴的图片作为内部资源，不自动创建目录条目；当前正文、历史及复制文档按引用共用。

- 移除正文图片不直接删除底层资源，无其他有效引用后才清理。
- 图片上传后正文未保存的资源保留宽限期后清理，时长待定；清理不能误删仍使用的资源。
- 独立资料图片通过目录上传生成可搜索、可关联条目，与编辑器内部资源区分。
- 图片访问检查文档权限，无绕过权限的公开 URL；复制、回收、转存和失权均需维护引用及访问上下文。

## 决策 24：正文图片输入及格式

用户已确认：正文支持选择本机图片、粘贴截图、拖入图片；格式 JPG、PNG、WebP，单张不超过 10MB。

- 可从本项目或同团队公共区选择已有上述图片，直接引用，不重复上传；禁止选择其他项目或跨团队资源。
- 粘贴网页不自动下载或直接加载外站图片，保留为链接，用户另行上传。外站图片不作为已托管资源或可完整导出的本机图片处理。
- 上传失败明确提示，本机预览不表示上传成功。
- 目录上传普通文件限制独立处理，不能将正文图片上限误作全部附件上限。
- 从资料条目选择图片后，该内部资源引用与条目移动/删除保护的关系待进一步明确，不能仅存裸资源 ID 绕过权限。

## 决策 25：未引用图片清理宽限期

用户已确认：上传成功但未被任何已保存正文、历史或其他有效资料引用的图片保留 24 小时，到期后进入后台清理；实际删除前再次检查引用。

- 所属文档仍有有效编辑锁时暂缓清理，防止编辑过程中资源消失；并发保存/引用创建与清理须原子协调。
- 本机草稿恢复时若图片已清理，提示重新上传，保留文字，不将草稿本身作为无限期服务器引用。
- 已有正常引用的图片不受此 24 小时期限影响。
- 服务器上传成功时记录创建时间；清理可延后执行，不承诺恰好在第 24 小时删除。

## 决策 26：正文图片固定内容

用户已确认：从本项目或同团队公共区插入图片时检查源资料权限，并建立文档独立资源引用，共用底层文件。正文固定使用插入时内容，不跟随源条目替换。

- 源条目重命名、移动、删除不破坏正文图片；替换源文件后正文仍引用原资源，需要时手动重新选择。
- 读取图片依据当前文档权限，底层资源清理检查独立正文及历史引用。
- 与任务/里程碑关联原资料并跟随最新内容的语义区分。

## 决策 27：标题编辑与锁

用户已确认：标题与正文受同一编辑锁保护；编辑者可在编辑器修改标题并自动保存，其他人不能从目录重命名。

- 无人编辑时，目录重命名使用短暂独占操作，与锁获取互斥，并校验同级重名及版本。
- 历史恢复仍只恢复正文，不回退标题。仅标题变动不生成正文历史；正文版本与条目元数据版本的设计需明确。

## 决策 28：回收站只读查看

用户已确认：有权限的团队成员可只读查看回收站正文、预览/下载文件；禁止编辑、替换、新增关联及直接移动，继续使用须先恢复。

- 目录打包导出仍不包含回收站内容，永久删除仅负责人/管理员。
- 回收站图片与文件通过带权限的回收站入口访问，不对无团队权限者开放。
- 到期或永久清理与正在进行的下载/预览的协调，及回收站正文历史查看范围仍需技术设计落定。

## 决策 29：分区与普通目录转换

用户已确认：分区与普通文件夹可通过移动相互转换，内容和引用不变。

- 空间至少保留一个正常分区；禁止移入自身或自身子目录。
- 包含编辑中文档时禁止移动；跨空间仍遵守先解除任务/里程碑关联等规则。
- 系统恢复分区的内部身份与层级变化如何协调须在实现中保证；不因允许移动而把非顶层目录错误用作恢复分区。

## 决策 30：外部链接维护

用户已确认：所有当前团队成员可修改外部链接标题与网址，保留资料身份和任务/里程碑关联，关联入口使用最新网址。

- 修改网址前提示关联影响范围并确认，记录修改人、时间及操作日志；并发修改校验版本，不静默覆盖。
- 仅接受 HTTP/HTTPS，不自动抓取外站内容；归档项目禁止修改。
- 首批不保留可恢复的网址历史；外部目标是否需要登录、是否仍可访问由外站决定，不保证平台权限能授权外站。

## 决策 31：回收站严格到期

用户已确认：以服务端记录的 30 天到期时间为准，到期立即禁止恢复、预览及下载，显示已到期待清理，不因后台尚未执行而延长可恢复期。

- 后台可稍后执行实体清理，删除前仍检查其他有效引用，不误删共享内容。
- 恢复和清理并发时服务端原子核对截止时间与状态，不能仅依赖界面倒计时。

## 决策 32：编辑期间导出

用户已确认：允许编辑期间导出，但仅导出服务器已保存内容，不包含本机草稿；界面提示导出最近已保存内容。导出开始时固定正文及图片引用，后续编辑不改变该次输出。

- 导出期间需保护所用资源不被替换/清理竞态破坏，具体使用短期导出引用或隔离快照在技术设计中明确。
- 导出下载仍校验当前访问权限，不因持有旧导出标识绕过失权检查。

## 决策 33：目录打包边界

用户已确认：仅打包所选目录内资料，不沿正文链接递归收集其他资料或下载外站内容。

- 不自动加入目录外任务或里程碑关联资料。
- 导出前提示部分链接需登录系统或联网访问。

## 决策 34：恢复后再次删除的期限

用户已确认：恢复后再次移入回收站，从此次删除重新计算 30 天；只在回收站内转存空间时保留原期限，不重置。

## 决策 35：目录导出统一快照

用户已确认：目录打包开始时固定目录结构、资料清单及已保存内容，后续移动/修改不改变本次输出；失败项重试使用同一快照。需要最新内容时重新发起导出。

## 决策 36：归档资料复制

用户已确认：允许从归档项目复制资料到同团队公共区或其他未归档项目，不改变原资料；新副本按既定独立身份、当前正文及资源共用规则处理。

- 身份、引用和期限按现有恢复规则处理，事务中防止整体恢复与单项恢复并发重复。

## 决策 44：视频预览范围

## 决策 45：正文大小

用户确认单篇结构化正文最大 5MiB，按服务器收到的正文 UTF-8 序列化大小校验；图片单独保存，不包含图片二进制。接近上限提示，超限拒绝保存并保留草稿，不截断正文。

## 决策 46：单次导出上限

用户确认单次最多 500 条资料（在线文档、上传文件、外部链接），最多 500MiB 压缩前内容，包含导出正文、文件及图片。

- 超限要求分目录导出，不静默遗漏；生成时发现超限明确标记失败，不输出看似完整的包。
- 使用后台任务及流式处理，不一次读取全部内容；这些是首批保护上限，不是已验证的性能承诺。

## 决策 47：团队总配额

用户确认首批不设置固定团队总存储硬配额，不承诺无限容量；保留单文件、正文和导出上限。空间不足明确拒绝新写入，保留原内容及本机草稿。生产磁盘和实际使用量核对后另定团队配额。

## 决策 51：默认阅读与显式编辑

用户确认：在线文档默认阅读，点击编辑才申请独占锁；仅查看不占锁。其他人编辑时展示编辑者，阅读者仍查看最近已保存内容。

- 自己编辑时显示保存状态、立即保存、保存版本、结束编辑。
- 结束编辑先保存，成功后释放锁并回到阅读；失败按既定草稿/离开规则处理，不静默丢弃或误报保存成功。

## 决策 52：统一资料列表

用户确认：采用单一表格列表，展示名称/类型、最近修改人、更新时间和行尾更多操作；文件夹与三类资料同表，文件夹优先。支持名称/更新时间排序，不新增卡片/网格等多视图。

- 排序及分页使用一致稳定的次序，文件夹优先规则不因切换排序丢失。
- 所有操作仍按权限、归档、编辑锁及引用状态显示与验证。

## 决策 53：当前目录新建与上传

用户确认：当前目录顶部“新建”菜单提供在线文档、文件夹、外部链接；在线文档可选空白或模板再填名称。另设上传文件按钮，支持拖入列表区域上传至当前目录。

- 创建前明确显示目标目录，根层仅提供新建分区；进入分区后才创建资料，不暗中创建位置或把文件堆入历史文件。
- 目录上传与编辑器拖图入口明确区分：列表上传生成独立资料，编辑器插图生成内部图片资源。

## 决策 54：标题搜索范围

用户确认：项目文档页按标题搜索本项目全部目录，团队资料页搜索当前团队公共区；展示路径，可打开或定位所在目录。默认不搜索回收站，回收站单独搜索；不跨空间混搜、不做正文搜索。使用文档页面自己的搜索框，与现有任务搜索区分。

## 决策 55：按需资料信息面板

用户确认：正文及预览保持简洁，点击资料信息再展开所属空间/目录、创建人、最近修改信息、文件类型及大小等适用字段、任务/里程碑关联与跳转入口。历史版本使用独立入口，不全部常驻正文侧边。

用户明确本轮不考虑移动端，Q56 的目录抽屉/单一内容区方案不作为已采用方案。文档系统首批设计、开发及新增界面验收聚焦桌面端；移动端/窄屏适配后续单独安排，不移除已有适配，不据此改动私聊的独立范围。

## 决策 57：历史版本面板

用户确认：历史版本采用独立面板，左侧显示时间、修改人及生成原因，右侧预览所选正文，可切换查看当前正文。恢复前提示仅恢复正文并确认，未持锁时先申请编辑锁，失败不执行恢复。

## 决策 58：空间独立回收站

用户确认：目录区域固定回收站入口，作为当前空间独立页面。展示名称、原路径、删除人、删除时间及到期时间，可浏览已删除文件夹并恢复子项；普通成员可恢复，负责人/管理员可永久删除。到期条目仅显示待清理状态，禁止内容访问及恢复。

用户确认：发起导出不阻塞继续工作，从当前空间导出任务入口查看进度、成功/失败项、重试、下载及有效期；明确区分部分与完整完成，不仅依赖一次性提示。
