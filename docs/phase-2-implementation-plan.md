# 第二阶段实施路径与执行记录

编写日期：2026-11-12，更新日期：2026-11-15（Asia/Hong_Kong）。当前状态：D0—D4 隔离版开发及开发侧检查完成，D5 组员人工验收进行中，生产未发布；私聊工作另行推进。

需求依据：[第二版需求基线](phase-2-requirements.md)。本文负责说明怎么做、按什么顺序做和如何判断完成；产品范围与权限规则以需求基线为准。本文不是功能完成记录，也不承诺尚未评估的人员工期。

## 1. 目标与使用方法

本轮先交付文档系统，再交付成员私聊，目标截止为 2026-11-25。保留现有账号、团队、项目、任务与附件，采用增量升级。甘特、拖拽及 REQ-58—65 的后续路线图不纳入本轮。

每次推进一个步骤，采用以下方式：

1. 阅读对应需求与当前实现，说明本步要解决的问题。
2. 形成可核对的设计：界面行为、数据关系、接口、权限、异常及兼容方案。
3. 实现最小的完整业务链路，再补齐同一步的边界情况。
4. 执行针对性检查，记录实际结果、失败项和遗留问题。
5. 达到完成条件后更新执行记录，再进入依赖它的下一步。

普通实现选择可以在需求边界内确定；范围或权限变化需要明确记录并由用户确认。不要把未执行的检查标为通过。开发过程中每次修改 Next.js 相关代码前，阅读安装版本 `node_modules/next/dist/docs/` 中的相关指南。

## 3. 第一步：建立实施基线（S0）

**目标：** 明确当前环境和风险，避免在错误数据或不完整基线上开发。

方法：

- 核对分支、工作区已有改动和适用的项目约定，保留他人的未提交内容。
- 核对本地运行方式、现有上传限制、附件保存方式、数据库实际结构及升级脚本使用情况。
- 在隔离的开发/测试环境准备两个团队、至少三个账号及已有附件、任务、里程碑样例。
- 执行适用的类型检查、lint、生产构建和现有测试，区分原有失败与新增失败。
- 落实参与成员、可投入时间和课程特殊提交要求，随后评估两批日期；若目标存在风险，提交具体取舍供用户决定。

产物：基线检查记录、测试环境说明、初步风险与投入记录。不得将本地 schema 视为生产迁移已完成的证据。

完成条件：能在隔离环境验证功能，已知问题有记录，旧数据有可核对的样例；不连接生产执行破坏性测试。

## 4. 第二步：文档系统数据与接口设计（D0）

**目标：** 先让前端、后端和数据库对同一套规则达成一致，再分配可并行的任务。

按以下顺序设计：

1. 画出项目空间、团队公共区、分区、文件夹及三类条目（在线文档、上传文件、外部链接）的关系。
2. 区分正文当前内容、并发版本号、最近 10 份正文历史，设计独占编辑会话和文件引用。
3. 列出操作矩阵：谁能查看、编辑、移动、删除、恢复、永久删除和导出；覆盖归档、离队、正在编辑和关联中的内容。
4. 列出接口请求、返回、错误、分页及事务边界。目录循环、跨团队操作、失锁和过期写入必须由后端拒绝。
5. 确定锁心跳/超时、保存节奏、容量限制、恢复重名、原目录消失、复制资源等待定细节。
6. 设计旧附件回填、项目删除转存及清理兼容方案，说明备份、重复执行行为和回退限制。

产物：文档系统设计说明、实际接口契约、迁移方案及权限矩阵。覆盖 REQ-06—22、39—53 中相关规则。

完成条件：能够完整解释“创建—编辑—关联—移动—回收—恢复—导出—清理”的数据变化，无待定项阻塞首条业务链路。D0 稳定后才能拆给不同成员独立实现。

## 5. 第三步：目录与统一资料管理（D1）

**目标：** 用户能够进入空间并组织资料。

方法：先实现“打开空间 → 创建分区/文件夹 → 创建条目 → 展示 → 重新加载”的完整链路，再增加重命名、标题搜索、移动、复制、引用清单及入口跳转。

- 提供三个可调整的默认分区和多层目录。
- 在线文档、文件、链接统一展示，按类型提供打开方式。
- 同团队跨空间移动保留历史；存在任务/里程碑关联时先解除，复制不改变原关联。
- 防止循环目录、跨团队操作及部分更新，恢复/重名不静默覆盖。
- 补齐文档与任务、里程碑的关联和解除关联操作，提供引用清单与跳转。

产物：目录界面、条目与关联接口、相应迁移和测试。依赖 D0；对应 DOC-01、02、07 及相关引用场景。

完成条件：正常目录操作可用，猜测 ID 或跨团队请求被拒绝，刷新后结果保持一致。

## 6. 第四步：在线编辑与恢复保护（D2）

**目标：** 文档能编辑、能保存，异常情况下不覆盖他人内容。

实施顺序：

1. 选择编辑器和正文存储格式，支持标题、列表、表格、图片、链接、代码块，处理非法内容及链接。
2. 实现服务端原子获取编辑锁；锁绑定编辑会话，同账号两个窗口也只能一个写入。
3. 实现自动保存，每次写入验证有效锁与正文版本；界面显示保存中、成功、失败及编辑者。
4. 实现退出保存与释放、心跳和超时释放；失锁立即停止保存。
5. 实现本机文字草稿及刷新恢复，先核对权限、锁和服务器最新内容；退出登录清除草稿。
6. 实现开始编辑前快照、变化后每 10 分钟恢复点、手动保存版本、历史查看/比较和恢复；无变化不重复生成，最近历史最多 10 份。

产物：编辑器、锁及正文接口、历史与草稿逻辑、竞争和断网测试。依赖 D0/D1；对应 DOC-03—05、12。

完成条件：双窗口竞争、同账号双窗口、断网、超时及失锁均不会覆盖最新正文；旧版恢复前有当前内容保护副本，历史引用图片不丢失。

## 7. 第五步：旧文件与资料生命周期（D3）

**目标：** 新文档系统与已有数据、删除流程安全衔接。

- 将旧附件确定性回填到“历史文件”，复用元数据与实体，核对数量、下载地址、任务和里程碑关联。
- 实现图片/PDF/浏览器支持的视频预览，Office 及其他不支持格式提供下载。
- 实现 30 天回收站、预计清理日期、文件夹整体恢复及管理员永久删除确认。
- 删除文件夹时递归检查引用和编辑锁；清理前检查当前正文、历史及其他有效引用。
- 归档项目保持阅读、搜索、导出，禁止编辑、移动和删除，后端不能被其他入口绕过。
- 项目删除时将目录和资料转存团队公共区，按“原项目名称＋删除日期”归档，并解除随项目删除的关联。
- 团队删除仅负责人操作，先处理项目，再展示公共资料影响与导出入口并明确确认。
- 验证锁与归档/删除并发、迁移失败及清理失败的恢复方式。

产物：旧数据迁移脚本、生命周期接口、后台清理、项目/团队流程调整。依赖 D0/D1，与 D2 共用锁及引用契约；对应 DOC-06、08、09。

完成条件：迁移前后旧文件可核对，资料转存完整，仍被有效引用的文件不会被清理，后台重复运行不会产生错误删除。

## 8. 第六步：模板与导出（D4）

**目标：** 团队能便捷创建资料，并完整交付成果。

- 通用模板：项目计划、会议纪要、周记录、阶段回顾、交付报告。
- 软件模板：复用通用模板，增加需求、技术设计、API、测试报告。
- 项目可选推荐组合或不选，文档按需从任意模板或空白创建，不自动铺满空文档，不提供团队模板库。
- 实现单文档 PDF、Markdown 导出；Markdown 包含引用图片。
- 目录打包保留结构，包含当前文档、上传文件和链接清单，不含回收站、历史及草稿。
- 列明失败项并支持重试，缺失内容的包不能显示完整成功。

产物：模板提纲、创建流程、导出与打包能力、可检查的导出样例。依赖 D1—D3 的格式与资源契约；对应 DOC-10、11、12。不包含 Word 导出。

完成条件：PDF 可读、Markdown 图片可用、压缩包结构与内容一致，越权导出被拒绝。

## 9. 第七步：文档系统集成验收（D5）

范围更新：按用户 Q56 指示，文档系统首批聚焦桌面端，新增移动端/窄屏适配暂缓；下文原窄屏要求不作为本批完成条件。其余主题、权限及回归要求保持，私聊范围不据此自动改变。

逐项执行需求文档 DOC-01—14，记录账号、场景、预期、实际结果及证据。补齐日夜主题、窄屏、加载失败与重试。

回归原任务、评论、检查清单、项目聊天、通知、里程碑和文件功能；执行类型检查、lint、生产构建及相关测试。演练备份、增量迁移和恢复步骤，形成接口/类型、部署、已知限制和验收记录。

完成条件：必要检查通过，失败项已修复或提交明确处理方案，完成记录与实际证据一致。文档批次验收与生产发布分开，本文不授权生产发布。

## 10. 第八步：私聊设计与实现（M0—M5）

文档契约稳定后结合投入安排开发；对外交付顺序仍为先文档、后私聊。遵守 REQ-23—38，不复用项目频道的可见权限作为私聊权限。

| 步骤 | 方法与产物 | 完成条件 |
| --- | --- | --- |
| M0 会话与权限 | 设计唯一用户对会话、消息、个人会话状态、已读、图片及重试标识；定义 API 与增量迁移 | 只有双方可读取；管理员无额外权限；无共同团队禁止发送但可读历史及撤回自己的消息；恢复共同团队后恢复发送 |
| M1 窗口与基础消息 | 成员入口、最近会话、桌面单窗口/最小化、窄屏面板、文字链接、历史分页 | 切项目不关闭聊天；服务端确认成功后才显示已发送；超时重试同一消息不重复 |
| M2 图片与撤回搜索 | 图片选择/粘贴/拖入、预览放大；仅 JPG/PNG/WebP，单张不超过 10MB；撤回确认和占位；会话内搜索定位 | 撤回不限时且仅本人；原图立即不可访问，后台清理；撤回正文不进入搜索，分页历史可定位 |
| M3 已读与聚合通知 | 前台且展开、消息实际可见才标记已读；已读回执、聚合弹窗、排序、免打扰和计数 | 打开列表不清未读；未读撤回扣数；免打扰仍计数但不主动轻提示；正在查看的会话不重复提示 |
| M4 草稿与可靠性 | 按联系人保存本机文字草稿、退出清除、发送中/失败/重试、离队提示 | 刷新可恢复文字；图片刷新需重新选择；失败不丢内容，失去权限后不发送 |
| M5 集成验收 | 执行 DM-01—08、相关测试、类型/lint/构建、原功能回归及迁移演练 | 完成逐项实际记录，主题/窄屏可用；正常聊天历史不自动清理，会话不随单个团队/项目删除而消失 |

普通文件通过文档系统上传后发送链接，链接仍检查原资料权限。首批不做私聊普通文件直传、全会话搜索、清空历史或已读开关。

## 11. 分工及并行边界

当前不预设人数或分配姓名。先完成 S0、稳定 D0，再按成员能力和投入把 D1—D4 分配为完整业务工作包。

- 为数据库/迁移、接口契约、共享状态和集成验收分别明确协调责任；责任可由同一人承担。
- 修改 `app/page.tsx`、共享类型、数据库结构、文件清理和通知前同步契约，避免各自实现不兼容模型。
- D2/D3/D4 可在共同契约稳定后适度并行；D5 依赖各功能完成。
- 私聊 M0 可以先设计，实际并行与两批日期依据投入评估，不能挤掉权限和数据保护验收。
