# 私聊设计边界与确认记录

更新：2026-11-18（Asia/Hong_Kong）。状态：产品边界与首版线框已获用户认可；M0 技术设计已完成，正式数据迁移和私聊实现尚未开始。依据 [需求基线](phase-2-requirements.md) REQ-23—38；本文记录新增和细化决定，不重复扩大范围。

## 已确认

| 决定 | 用户确认的边界 |
| --- | --- |
| Q1 联系人 | 从共同团队成员中选择；不做全站用户搜索、陌生人私聊、好友申请。失去共同团队的既有会话保留，可读历史、撤回自己的消息，禁止发送。 |
| Q2 项目上下文 | 从任何项目入口进入双方统一私聊，不归属项目、不自动附带项目资料、不授予文档权限。任务/资料手动发链接，打开仍检查原权限。 |
| Q4 窗口状态 | 最小化和关闭都保留会话、历史及文字草稿；最小化留恢复入口，关闭后从最近会话/成员入口重开。只展开一个会话；新消息不自动弹窗、不抢焦点。 |
| Q3.1 文字 | 支持换行、链接自动识别、保留粘贴文本换行；不做字体/颜色/标题等富文本工具栏。 |
| Q3.2 引用回复（新增首批范围） | 可针对一条消息回复，发送时附原消息摘要，点击摘要定位原消息。原消息撤回后，所有引用摘要同步变为“原消息已撤回”，不暴露原内容。 |
| Q3.3 修改 | 首批不编辑已发消息，纠正通过撤回后重发。 |
| Q3.4 表情 | 允许系统 emoji 输入/粘贴；不做表情商店、自定义贴图或消息表情回应。 |
| Q3.5 其他媒体 | 转发、语音消息、语音通话和视频通话留到后续，不纳入首批。 |
| Q5 可回复对象 | 可回复双方发送的文字、链接及图片，包括自己的消息；已撤回消息不可新建回复。 |
| Q6 引用层级 | 每条消息仅引用一个直接原消息，不展开嵌套引用链；回复已有引用的消息时，摘要仅显示该消息本身，可逐条定位追溯。 |
| Q7 引用摘要 | 显示发送者姓名及最多两行文字摘要；链接按文字显示，图片显示“[图片]”，不复制缩略图。点击定位原消息。原消息撤回后摘要统一隐藏为“原消息已撤回”，回复者自己写的内容保留。 |
| Q8 引用草稿 | 引用目标随联系人文字草稿保留，切换、关闭及刷新可恢复，可单独取消引用。发送前原消息已撤回时提示失效、保留输入文字，用户确认取消引用后再发送，不自动改变发送内容。 |
| Q9 文字上限 | 单条最多 5,000 个字符，纯空白不可发送；接近上限提示，超限保留输入并提示拆分，不自动截断。 |
| Q10 发送键 | 桌面 Enter 发送、Shift+Enter 换行，保留发送按钮；中文输入法选词期间 Enter 不发送。窄屏回车换行，通过按钮发送。 |
| Q11 图片消息 | 每条为文字或一张图片，不做图文混排/相册，一次选择一张。选择/粘贴/拖入先预览、确认后发送；图片可附单层引用，说明文字另发。每条独立显示发送/重试/撤回/已读状态。 |
| Q12 排序与免打扰 | 最近会话按最新消息时间排序，打开会话/已读回执不改变排序；不做置顶、隐藏、删除会话。免打扰仅关闭主动轻提示，保留未读及聚合列表。轻提示只显示发送者和“收到新消息”，不显示正文/图片。 |
| Q13 更新与断网 | 自动更新消息、撤回、已读及未读；网络异常明确提示并自动重试，保留输入，重连补齐消息，不将缺少更新视为没有新消息。 |
| Q14 阅读与滚动 | 位于底部时新消息自动进入视野；向上翻历史时不强制回底，显示“有新消息”入口；未进入可视区域的消息保持未读。 |
| Q15 搜索定位 | 仅搜索当前会话文字/链接，展示发送者、时间及匹配摘要；结果可加载历史、定位并高亮原消息，提供回到最新入口，不清草稿；不做图片 OCR，撤回内容不可搜索。 |
| Q16 发送失败 | 失败项留在原会话，可重试、复制文字或移除本机失败项，不阻塞后续消息。重试沿用原消息编号；状态不确定先核对服务端结果，不把已送达消息当作未发送删除。移除失败项不等于撤回。 |
| Q17 多窗口同步 | 同账号各窗口同步已发送消息、撤回、已读及未读；任一窗口实际阅读后同步清除对应未读。窗口最小化/关闭及当前联系人独立，不强制其他窗口切换。 |
| Q18 重开位置 | 有未读时从第一条未读开始并显示未读分界，无未读时显示最新消息。打开会话不自动将全部消息标为已读，仍依实际可见性确认。 |
| Q19 关键词匹配 | 当前会话按连续关键词匹配，忽略英文大小写，链接地址参与搜索；不做分词联想、拼音、正则或高级筛选。 |
| Q20 免打扰归属 | 免打扰按账号保存，换浏览器仍生效；只影响本人、不通知或影响对方，保留角标、聚合列表和正常已读回执。 |
| Q21 草稿冲突 | 同账号本机多窗口编辑同一联系人草稿时，不自动合并或覆盖正在输入的文字；检测到其他窗口更新时提示，可比较、复制或选择采用。刷新恢复时明确展示不同草稿，不跨设备同步。 |
| Q22 重试排序 | 已发送消息按服务端实际接收顺序排列；失败消息重试成功时按此次接收位置入列，不插回旧位置。本机失败时间不作为对方接收时间。 |
| Q23 链接打开 | 仅 HTTP/HTTPS 识别为可点击链接，新标签页打开；不自动抓取网页或生成预览卡片，其他协议显示普通文字。站内任务/文档链接重新鉴权，发送不授予权限。 |

Q1/Q2/Q4 先获确认，随后 Q3.1—Q3.5 全部获确认；不能把先前 Q3“待定”误作为仍未决定。

## 整体边界摘要（已确认）

Q1—Q23 的上述决定均已确认（Q3 按 Q3.1—Q3.5 拆分）。本轮产品边界汇总如下，用户已认可据此制作的线框；不表示已完成实现。

- 会话：共同团队成员可发起，同一对用户全平台唯一，只有双方可读，管理员无额外权限；失去全部共同团队后禁发、历史保留且可撤回本人消息，重新拥有共同团队可恢复发送。
- 窗口：团队/项目成员入口、最近会话与通知进入；每个页面展开一个，支持最小化/关闭，切项目保留；窄屏使用面板，新消息不强制展开或抢焦点。
- 消息：文字/链接或单张图片，文字 5,000 字符；JPG/PNG/WebP 单张 10MiB，图片先预览确认；系统 emoji、单层引用回复、历史分页、会话内关键词搜索、本人不限时确认撤回、已读回执。
- 阅读与通知：实际前台可见才已读；看历史时不拉回底部，显示新消息入口；聚合未读消息/会话数，个人免打扰跨浏览器生效，不展示正文轻提示。
- 可靠性：服务端确认才已发送，自动同步及断网重连补齐；失败重试幂等、状态不确定先核对；按服务端实际接收顺序排列。
- 草稿：文字与引用按账号/联系人本机保留，关闭/切换/刷新可恢复，退出清除；图片刷新需重新选择，多窗口草稿冲突明确提示、不静默覆盖。
- 排除：陌生人/好友体系、群聊、普通文件直传、富文本工具栏、消息编辑、转发、表情回应/贴图库、音视频、跨会话搜索、置顶/隐藏/删除会话、清空聊天记录、自动网页卡片及跨设备草稿同步。

底层消息关系、接口、权限和并发方案由实现方设计，不以客户端复制摘要代替撤回后的服务器访问控制。具体窗口布局和各状态在线框阶段审查；范围有新增时再明确确认。

底层数据、接口、事务和测试计划见 [私聊 M0 技术设计](phase-2-private-chat-technical-spec.md)。新增引用回复已纳入测试计划，原交付日期仍需结合实施进度评估。

## 首版线框审查（2026-11-18）

已制作独立可点击审查页 `private-chat-review.html`，保存在当前聊天的审查产物目录，未接入应用和数据库。展示成员入口/最近会话、单窗口最小化与关闭、切项目保留输入、文字发送/单层引用、撤回确认、搜索定位、模拟图片预览、个人免打扰及断网/离队/草稿冲突/阅读历史场景。窄屏布局可切换或缩小视口查看。

无头 Edge 已检查发送、引用、最小化恢复、离队禁发、失败重试、搜索、图片预览及 390px 无页面横向溢出，未发现脚本运行错误；已保存桌面及窄屏截图。所有状态和权限均为内存模拟，不能替代服务端鉴权、真实图片上传、跨刷新草稿、多窗口同步或可见性已读测试。更早历史入口只提示分页设计，当前未演示实际分页数据。

用户已明确认可线框“展示没问题，可以使用”，并授权推进 M0；线框作为界面实现依据，不作为私聊真实功能完成证据。
