# 第二版需求基线与实施交接

更新：2026-11-18（Asia/Hong_Kong）。状态：文档系统已交付隔离版，私聊继续确认边界；需求确认不代表功能已实现或已验收。

> 2026-11-23 范围调整：日常文档维护以项目空间为入口。保留项目默认分区、多层目录和系统模板。新关联从本项目选择，移动和复制的目标为同团队项目。原团队资料和历史引用继续保留。下文涉及团队公共区的条目记录原基线。

## 1. 产品目标与交付边界

服务大学课程项目中的学生团队，兼顾软件开发与通用课程协作；教师仅接收成果，不引入教师管理流程。不强制每日会议或固定记录节奏。

- 本轮截止：2026-11-25。第一批文档系统，第二批私聊，分别验收。
- 优先保证文档系统完整可用；私聊延期风险须提前提交具体取舍，由用户决定，不自行删减功能。
- 有其他成员参与，分工和投入待定；两批具体日期须评估后安排。
- 工作池、迭代/阶段推进、阻塞、成果确认、回顾改进及健康总览属于后续路线图，不加入本轮两周范围。甘特与拖拽详细方案尚未重新确认。
- 保留已有账号、团队、项目、任务和附件，增量升级；生产发布单独处理。

现有架构见 [第一版技术概览](v1-technical-overview.md)，部署见 [部署指南](deployment.md)。本文件取代此前需求草稿；旧稿未确认的接口、容量参数及甘特/拖拽细节不再作为实施要求。

## 2. 已确认需求索引

REQ 编号保持稳定，便于工作包和测试追踪。REQ-01—57 为当前范围及交付约束，REQ-58—65 为后续路线图。后续条目对前面概要作具体补充。

| 编号 | 主题 | 确认内容 |
| --- | --- | --- |
| REQ-01 | 目标用户 | 第一目标仍为大学课程项目中的学生团队，覆盖组长与普通成员；暂不引入教师管理流程，教师仅接收项目成果。 |
| REQ-02 | 问题与优先级 | 核心问题为成员沟通、内容沉淀、任务安排与跟进。先解决私聊和文档管理，再优化任务安排与跟进；甘特与拖拽的具体方案仍待本轮访谈复核。 |
| REQ-03 | 私聊 | 同团队成员可进行一对一文字沟通，支持快速协调、问题求助与单独反馈；保留项目公开频道用于团队讨论。详细规则见 REQ-23—38。 |
| REQ-04 | 文档覆盖范围 | 管理过程记录、项目方案与交付成果，包括会议纪要、调研笔记、需求文档、API 文档、报告、演示文稿、设计文件、代码仓库链接及视频等。 |
| REQ-05 | 记录节奏 | 适应学生课程压力，不强制每日会议或每日记录；支持每周、每阶段及按需记录。 |
| REQ-06 | 文档归属 | 每个项目拥有独立文档空间；另设团队公共资料区，保存跨项目使用的规范、模板与参考资料。 |
| REQ-07 | 默认分区 | 采用“项目文档”“协作记录”“交付成果”三个默认分区，分别组织需求/API/设计等资料、会议/周记录/阶段回顾以及最终交付内容。 |
| REQ-08 | 升级方式 | 保留现有账号、团队、项目、任务、附件等数据，在第一版基础上分批升级交付。 |
| REQ-09 | 需求维护 | 对话中产生的需求持续写入本项目需求文档，并标明确认状态。 |
| REQ-10 | 目录自定义 | 允许重命名、增加和删除分区，并在分区内建立多层文件夹；非空目录删除见 REQ-17、21、43。 |
| REQ-11 | 统一管理 | 在线文档、上传文件和外部链接进入同一目录体系，统一分类、标题搜索和关联；按内容类型提供适当的打开方式，具体预览格式待确定。 |
| REQ-12 | 首批文档能力 | 包含分类、文件夹、标题搜索、在线编辑、自动保存、多人修改冲突提示、修改人、更新时间、版本历史与恢复、重命名、移动、回收站与恢复、里程碑关联，并保留已有附件。详细规则见后续相关需求。 |
| REQ-13 | 编辑内容 | 首批在线编辑支持标题、列表、表格、图片、链接、代码块等常用内容；上传的 Word、PPT、Excel 先支持保存、下载及适用格式预览，不提供系统内直接编辑。具体可预览格式待细化。 |
| REQ-14 | 单人编辑锁 | 同一在线文档同一时间仅允许一人编辑，其他人可阅读；显示锁定状态及编辑者，正常退出或异常离线后释放编辑状态，保护未保存内容，避免多人同时修改。异常恢复及版本生成见 REQ-16、20、50，锁超时数值待设计。 |
| REQ-15 | 权限原则 | 首批沿用团队权限，不增加逐篇文档授权。具体管理权限见 REQ-17。 |
| REQ-16 | 锁释放与草稿 | 编辑时获取独占锁，阅读者可见编辑者；正常退出保存后释放，保存失败提示保留草稿；异常关闭或断网后超时释放。失锁后停止自动保存并保留草稿，重新获取锁后才能继续；首批不提供强制抢锁。 |
| REQ-17 | 管理权限 | 普通成员可整理目录、移入回收站及恢复；永久删除仅限团队负责人和管理员。删除非空文件夹前提示范围，文件夹及内容一起进入回收站，支持整体恢复。 |
| REQ-18 | 导出交付 | 在线文档支持 PDF、Markdown 导出；支持按目录打包下载文件和导出的文档，外部链接附为链接清单。教师接收导出成果，首批不提供公开分享链接；Word 导出首批不做，见 REQ-51。 |
| REQ-19 | 有限历史 | 在线文档保留最近 10 个正文历史版本，自动保存合并处理，不逐次生成历史。图片附件不随正文版本重复复制，但历史仍引用的资源须保留。上传文件首批只保留当前文件，不自动保留旧二进制版本；历史生成见 REQ-20，资源清理检查引用。 |
| REQ-20 | 历史生成与恢复 | 开始一次编辑前保留当前正文；编辑期间每隔 10 分钟有变化时补充恢复点，并提供“保存版本”按钮。自动保存持续保护当前正文；恢复旧版前先保留当前内容，再生成新的当前版本，仍遵守最近 10 个历史版本上限；无变化不重复生成。 |
| REQ-21 | 回收站期限与编辑保护 | 删除内容保留 30 天，显示预计清理日期，到期自动清理；永久删除再次确认。编辑中的文档暂不允许移动或删除，包含该文档的文件夹同样受限并提示等待编辑结束。清理资源前检查正文及历史引用。 |
| REQ-22 | 跨空间整理 | 同团队内允许项目空间与团队公共区之间移动或复制文档，不支持跨团队移动。移动保留历史，复制生成独立文档；已关联任务或里程碑的文档须先解除关联才能跨空间移动，复制不改变原文档及其关联。 |
| REQ-23 | 私聊入口与窗口 | 团队成员列表、项目成员入口可发起私聊；当前页面聊天小窗、最近会话与未读数量；切换项目不关闭聊天，切换联系人保留当前未发送草稿。桌面同时展开一个窗口，支持最小化、关闭及重新打开；窄屏使用聊天面板。 |
| REQ-24 | 首批私聊能力 | 支持文字、链接、历史分页、失败重试和未读提示；图片、撤回、消息搜索及向对方展示已读状态均纳入首批。首批不支持普通文件直传，见 REQ-26。文档链接仍受原内容权限限制。 |
| REQ-25 | 会话与隐私 | 同一对用户全平台复用一个私聊会话，只有双方可查看，负责人/管理员无额外查看权限。双方失去所有共同团队后历史可读、禁止发送，但可撤回自己的消息；重新拥有共同团队后恢复发送。会话不随单个团队或项目删除而清空。 |
| REQ-26 | 私聊图片 | 支持选择、粘贴和拖入图片，发送前预览，发送后点击放大；首批 JPG、PNG、WebP，单张不超过 10MB。普通文件暂通过文档系统上传后发送链接，不提供私聊直接发送普通文件。 |
| REQ-27 | 不限时撤回 | 发送者可撤回自己发送的文字或图片，不设时间限制；双方显示“消息已撤回”，管理员不能代替他人撤回。撤回内容不参与搜索，原图片链接不可再读取；不能收回对方已看到或下载的内容。离队后撤回和清理见 REQ-30、31。 |
| REQ-28 | 会话搜索 | 当前会话内按关键词搜索文字及链接，点击结果定位原消息；撤回消息不进入结果。首批不含图片文字识别及跨全部会话搜索。 |
| REQ-29 | 已读回执 | 仅聊天展开、页面在前台且消息进入可视区域时标为已读；自己发出的消息显示未读/已读。最小化、关闭或仅收到通知不算已读；首批统一开启回执，不提供开关。已读不表示已处理。 |
| REQ-30 | 离队后撤回 | 双方失去全部共同团队后，禁止发送新消息，但仍允许双方各自撤回自己发送的旧消息；此规则为历史只读的明确例外。 |
| REQ-31 | 撤回处理 | 撤回前二次确认；撤回后保留“消息已撤回”占位及原发送时间，不提供正文查看或恢复。图片立即禁止系统访问，后台清理对应文件；不能收回对方已下载或看到的内容。 |
| REQ-32 | 私聊聚合通知 | 新消息提醒嵌入现有通知系统，汇总提示新消息数量，不逐条生成消息通知。点击聚合通知弹窗列出所有有新消息的会话，并可跳转对应聊天。保留最近会话排序及未读角标，不自动展开聊天；正在查看对应会话时不重复提示。支持会话免打扰，仍保留未读角标；首批不加声音、邮件或浏览器系统通知。具体计数见 REQ-33—35。 |
| REQ-33 | 聚合计数与已读 | 聚合入口按未读消息条数计数，并显示涉及会话数；点击通知或打开会话列表不清空未读。只有进入对应会话、页面在前台且消息进入可视区域才算已读，未看到的消息保持未读。 |
| REQ-34 | 未读会话弹窗 | 展示头像、姓名、最新消息摘要、时间及未读数量，按最新消息时间排序；图片摘要为“[图片]”。点击会话收起列表并打开聊天，可再次从通知入口查看其余未读会话；全部读完显示“暂无新消息”，历史会话从最近会话进入。 |
| REQ-35 | 免打扰与撤回计数 | 免打扰会话仍计入总未读并出现在聚合弹窗中，但不产生主动轻提示。未读消息撤回后从未读数扣除，撤回占位不产生新未读提醒。 |
| REQ-36 | 发送可靠性 | 消息显示发送中、失败及已发送状态；失败保留内容并支持重试，超时后重试同一消息不重复发送。失去共同团队时明确提示不可发送并保留文字供复制；图片上传失败可重试，服务端确认成功后才显示已发送。 |
| REQ-37 | 私聊草稿 | 未发送文字按联系人保存在本机，切换项目、关闭窗口及刷新后可恢复，不跨设备同步；退出登录清除本机私聊草稿。未发送图片刷新后需重新选择。 |
| REQ-38 | 私聊历史保留 | 首批不自动清理正常聊天历史，分页加载旧消息；不提供清空聊天记录，发送者删除已发送内容使用撤回。已撤回图片按既定规则清理；后续依据实际容量制定归档策略，数据库备份独立管理。 |
| REQ-39 | 归档项目文档 | 项目归档后文档仍可阅读、搜索及导出，不允许编辑、移动或删除；需要修改时由负责人或管理员先恢复项目。团队公共资料区保持可用；项目删除时转存资料，见 REQ-42。 |
| REQ-40 | 历史附件整合 | 已有项目文件和任务附件统一展示在项目文档空间的“历史文件”目录，保留原下载地址、任务关联及里程碑关联，不重复存储。同一文件在各入口引用同一份内容，目录内移动不影响关联；删除被引用文件时提示影响范围，须先解除关联再删除，见 REQ-43。 |
| REQ-41 | 默认模板 | 提供默认文档模板。模板组合、清单及使用规则见 REQ-44—48，具体提纲待设计。 |
| REQ-42 | 删除项目保留资料 | 删除项目时将文档、文件及目录结构转存团队公共区，以“原项目名称＋删除日期”单独归档；删除前展示资料数量及去向。保留资料，原项目任务和里程碑关联随项目删除解除；作为项目删除专门流程，无需逐条手动解除关联。 |
| REQ-43 | 引用删除保护 | 被任务或里程碑引用的文档、文件须先解除关联才能移入回收站；提供引用清单及跳转入口。删除文件夹时检查其中所有内容的引用，存在未解除引用时阻止删除。项目删除仍执行 REQ-42 的专门保留与解除关联流程。 |
| REQ-44 | 项目模板组合 | 首批提供“通用课程项目”和“软件开发项目”两组文档模板。通用组包含会议纪要、周记录、阶段回顾、交付报告；软件组在通用模板基础上增加需求、API、测试等专业文档。创建项目时可选择模板组合或不选，文档按需从模板或空白创建，不自动生成整套空文档。不据此预设项目阶段、任务及交付要求；具体模板字段继续细化。 |
| REQ-45 | 通用模板清单 | 通用组包含项目计划、会议纪要、周记录、阶段回顾、交付报告。项目计划记录课程目标、成果要求、成员分工及阶段安排；仅作为文档内容，不自动创建任务或里程碑。 |
| REQ-46 | 软件模板清单 | 软件组复用全部通用模板，增加需求文档、技术设计、API 文档、测试报告；首批使用简明提纲与填写提示，不强制采用复杂企业文档规范。 |
| REQ-47 | 模板不限制内容 | 模板仅提供文档结构预设。新建文档可选择任意系统模板或空白创建；项目类型仅影响推荐顺序，不限制选择。创建后成员可自由编写并增删、修改结构，切换模板推荐组合不修改已有文档。 |
| REQ-48 | 首批不做团队模板库 | 首批不提供将文档另存为团队模板及团队模板管理功能；使用现有系统预设、空白创建及文档复制满足初期需求。 |
| REQ-49 | 附件预览范围 | 首批支持图片、PDF 及浏览器支持的常见视频格式预览；Word、Excel、PPT 等先提供下载并使用本地软件打开。不引入完整 Office 在线预览服务；不支持的格式显示下载入口。 |
| REQ-50 | 在线文档草稿恢复 | 保存失败时在本机保留文字草稿，刷新或关闭后可恢复；重新打开先检查当前权限、编辑锁及服务器最新版本，不直接覆盖服务器正文。提供查看最新内容、复制草稿及获取锁后继续编辑；失去权限时不上传草稿，失锁时禁止保存。退出登录清除本机草稿；未上传成功的图片需重新选择。 |
| REQ-51 | Word 导出后置 | 首批不支持 Word 导出；提供已确认的 PDF、Markdown 及目录打包。若后续课程要求可编辑 Word，再单独规划。 |
| REQ-52 | 团队删除 | 仅团队负责人可删除团队；须先处理所有项目，再明确确认永久删除团队公共资料。删除前展示影响范围并提供导出入口；私聊按既定规则保留，不随团队删除清空。 |
| REQ-53 | 打包导出范围 | 默认导出当前版本并保留文件夹结构，包含上传文件、在线文档和外部链接清单，不含回收站、历史版本及未保存草稿。在线文档可选 PDF 或 Markdown，Markdown 包含引用图片；逐项列出导出失败内容并支持重试，不将内容缺失的包标为完整成功。 |
| REQ-54 | 期限与交付顺序 | 以 2026-11-11（Asia/Hong_Kong）为确认日，两周后即 2026-11-25 为本轮文档系统与私聊交付截止日期。分两批验收，先文档系统、后私聊；任务安排与跟进优化在两者完成后继续讨论，不默认包含在本次两周交付内。各批具体日期及范围可行性待评估。 |
| REQ-55 | 验收方式 | 使用两个团队、至少三个测试账号，验证正常使用、越权访问、成员离队、双窗口编辑、断网重试及旧数据兼容；整理逐项验收清单并记录实际结果，再确认每批完成。 |
| REQ-56 | 开发资源 | 有其他成员参与开发，具体成员分工及投入比重尚未确定；不按仅用户与助手两人开发估算排期。 |

### 接口与数据设计边界

- API 命名及具体字段由实现设计确定，不把建议路径视为已存在接口。
- 每个正文、历史、锁、文件下载、导出及目录操作均检查当前登录身份和团队权限。锁绑定具体编辑会话，服务端原子获取；同账号双窗口也不能同时写入。
- 写入同时验证有效锁及正文版本，拒绝过期写入。恢复版本同样受锁与版本校验约束。
- 正文当前版本、可恢复历史与并发版本号分别设计，不能把每次自动保存等同历史快照。
- 目录归属、跨空间移动及引用校验在服务端执行，防止跨团队访问、循环目录和部分更新。
- 附件元数据与物理内容复用。清理前检查当前正文、历史及其他有效引用，不能因移除目录条目误删仍使用的文件。
- 已有库使用增量迁移及确定性回填，不运行 seed 覆盖业务数据。迁移说明包含备份、顺序、重复执行行为及回退兼容限制。
- 新模块封装面板与状态逻辑，复用现有认证、请求安全及文件维护机制，不继续集中堆入根组件。

## 5. 第二批：私聊实施与验收边界
