# v7.4 生产部署方法

测试服务器验收通过后，将同一个提交发布到现有阿里云生产服务器。项目目录为 `/var/www/agile-platform`，systemd 服务名为 `agile-platform`，生产 PostgreSQL 16 使用端口 `5433`。发布前核对 [测试放行标准](testing.md#缺陷复测与上线放行) 和 [服务器交接手册](server-handoff.md)。

## 部署前检查与备份

1. 从测试验收记录取得完整提交号，在生产仓库执行 `git fetch origin`，确认该提交可用。检查生产工作区，并核对当前生产提交与验收提交之间的数据库变更，列出本次需要执行的增量迁移。
2. 安排维护窗口。按交接手册第 7 节停止服务并确认停止，再记录当前生产提交号，备份 PostgreSQL 数据库和 `uploads/` 附件目录。
3. 确认备份命令成功。用 `pg_restore --list` 检查数据库归档，用 `tar -tzf` 检查附件归档。如果附件目录当时不存在，记录该状态。将备份位置和旧提交号写入发布记录。

## 更新、迁移与构建

1. 以 `agile` 用户进入项目目录，使用 `git switch --detach <验收通过的完整提交号>` 切到目标版本，再用 `git rev-parse HEAD` 核对提交号。
2. 运行 `npm ci --include=dev`。保留生产 `.env.local` 和 `uploads/`。
3. 按预先核对的顺序执行本次需要的增量迁移。如果本次没有数据库变更，跳过迁移。
4. 运行 `npm run build`。迁移或构建失败时立即停止发布，记录错误并进入回退判断。
5. 迁移和构建成功后，由 root 执行 `systemctl start agile-platform`，结束维护停机。

## 上线验收

1. 用 `systemctl status agile-platform --no-pager -l` 确认服务正常运行，通过生产 HTTPS 地址确认站点可访问。
2. 用验收账号检查登录、项目与任务、文档与附件，并复验图标栏文字注释、纵向滚动、字号和栏宽。操作与预期结果见 [测试要求](testing.md#测试要求)。
3. 记录发布提交、验收结果和验收人。全部通过后将发布标记为完成。

## 停止发布与回滚

1. 迁移或构建失败时立即停止发布。服务启动失败、生产 HTTPS 无法访问，或核心流程出现阻塞时，启动回滚。
2. 停止服务并保留失败日志和当前数据。核对旧版代码与当前数据库和附件的兼容性，检查备份后是否有新增写入。涉及数据恢复时，先据此确定恢复范围和新增写入的处理方式。
3. 确认数据库和附件与旧版兼容后，用 `git switch --detach <部署前记录的提交号>` 切回旧版，重新执行 `npm ci --include=dev` 和 `npm run build`，再启动服务。需要恢复数据时，先完成上一步确定的恢复操作，再启动旧版。
4. 重新检查服务状态、生产 HTTPS 和核心流程，记录回滚结果。
