# 动效丝滑优化（terry/smooth-motion）

从 `terry/personal-suite` 新建分支，不动任何已有分支，也不改动已有样式规则——只**追加**一个独立的 `app/motion.css`，并在 `app/layout.tsx` 里加一行 import。

## 为什么这么做（用 grill-me 拷问后的结论）

用 `grill-me`（深度追问式方案审查）把方案拆成决策分支后发现：真正的痛点**不是"缺动画"**，而是**缺统一节奏**——全项目只有 24 处零散 `transition`，时长 `.15s / .18s / 1.6s` 混用、曲线各不相同，视图切换还是条件渲染硬切，所以整体显得一顿一顿。

因此策略是「**先立 token，再补进场与反馈**」，而不是到处堆 `@keyframes`。

### 决策表

| 决策分支 | 结论 | 依据 |
|---|---|---|
| 要不要统一动效 token | 要：3 档时长 + 3 条曲线 | 现状无统一变量 |
| 改 CSS 还是动 React 逻辑 | 只补 CSS，零功能逻辑改动 | 视图切换是条件渲染，容器级进场动画即可覆盖 |
| 优化哪些生硬点 | 主题切换、视图/面板、卡片列表、按钮反馈、弹层 | 现有仅 toast/skeleton/drawer 有动画 |
| 性能怎么保证丝滑 | 只动 `transform / opacity / 颜色`，不碰布局属性 | 避免重排抖动 |
| 无障碍 | 全局 `prefers-reduced-motion` 兜底 | 现有支持零散，正好收敛 |
| 会不会破坏深浅主题 | 只追加、选择器限定范围、不覆盖已有规则 | 主题是 `html[data-theme]` 变量切换 |

## 具体做了什么

- **统一 token**：`--motion-fast/base/slow`（140/220/360ms）+ 三条缓动曲线（通用减速 / 进场 / 轻微回弹）
- **主题切换过渡**：给大面积承载底色的容器加 `background-color / color / border-color / box-shadow` 平滑过渡（CSS 变量本身无法过渡，作用在消费它的元素上）
- **交互反馈**：按钮统一 hover/active 过渡，按下 `scale(.94)` 给出触感，主题按钮 hover 旋转、悬浮入口位移
- **视图/面板进场**：工作台主内容、效率中心面板、设置/登录卡片淡入上移（`motion-enter`）；弹层用更轻的 `motion-pop`，遮罩淡入
- **卡片错峰**：今日卡片、看板卡片、记事卡片、待办列表按序 stagger（0/45/90…ms），避免整屏一起弹
- **进度条**：宽度变化平滑
- **无障碍**：一个 `@media (prefers-reduced-motion: reduce)` 统一关掉本层全部动画/过渡/位移，与已有零散规则并存不冲突
