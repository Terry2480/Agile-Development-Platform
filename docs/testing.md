# v7.4 测试要求与执行方法

按本地验证、测试服务器验收、生产部署的顺序推进。测试基线为 `main` 上的 `17a6dc7`。每轮测试记录实际提交号，测试服务器验收与待发布版本使用同一提交。

## 测试要求

| 范围 | 操作与预期结果 |
| --- | --- |
| 图标栏文字注释 | 在本次改动涉及的页面检查图标及文字注释，确认文字清楚、与对应操作一致。 |
| 纵向滚动 | 用内容超过可视区域的页面滚动到底部，再返回顶部，确认首尾内容均可访问。 |
| 字号和栏宽 | 用常用窗口宽度查看页面，确认正文和标签易读，关键内容没有重叠或被截断。 |
| 登录 | 使用测试账号登录，确认能进入工作区。 |
| 项目与任务 | 打开测试项目，查看任务，并更新一条测试任务，刷新后确认更新保留。 |
| 文档与附件 | 打开一份测试文档，上传并下载一份测试附件，确认文档可读、附件可打开。 |

## 本地验证

1. 确认当前提交，安装依赖，并在 `.env.local` 中连接本地测试数据库。数据库准备见 [本地开发说明](../README.md#本地开发)。
2. 依次运行以下命令，记录每项结果。

   ```bash
   npm test
   npm run lint
   npm run build
   ```

3. 运行 `npm run dev`，用浏览器逐项验证图标栏文字注释、纵向滚动、字号和栏宽。

## 测试服务器验收

1. 本地验证通过后，将对应提交部署到测试服务器。
2. 用测试账号和测试数据复验本次改动，并按表格快速回归登录、项目与任务、文档和附件。
3. 记录提交号、测试环境、测试人、用例结果和缺陷。记录缺陷时附上复现步骤、预期结果和实际结果。

## 缺陷复测与上线放行

- `npm test`、`npm run lint` 和 `npm run build` 必须全部通过，本地浏览器验证和测试服务器验收均须通过。
- 上线前须修复全部阻塞缺陷，并复测原问题及受影响的核心流程。修复产生新提交时，按新提交执行上述验证和验收。
- 轻微显示问题经上线负责人确认后，可以记录并延期处理。
- 满足以上条件后进入生产部署。
