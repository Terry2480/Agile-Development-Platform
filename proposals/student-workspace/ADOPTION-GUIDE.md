# 采用指南

## 选择方式

队友可以选择三种使用方式：

### 只看设计

只阅读本目录的功能地图、数据库说明和实现代码，不合并任何提交。

### 运行平行实现

进入 `implementation/`，单独安装依赖并运行。它不会影响仓库根目录的基础项目。

### 按功能采用

从 Pull Request 中选择需要的提交，使用 `cherry-pick` 应用到自己的开发分支。

## 推荐的最小版本

课程项目演示建议采用：

1. 基础工作台
2. 用户与团队
3. 项目与任务

大创、竞赛和科研项目建议追加：

4. 项目资料
5. 时间线

AI、Agent API 和飞书功能建议在核心流程稳定后再评估。

## 采用前检查

- 确认当前分支不是 `main`。
- 先创建备份分支。
- 阅读对应提交的文件列表。
- 检查新增依赖是否与当前 `package.json` 冲突。
- 检查数据库 schema 是否需要同步。
- 检查新增环境变量是否有真实值。
- 不复制 `.env`、`.env.test` 或任何密钥。

## 采用后检查

```powershell
npm install
npm run lint
npm run build
git diff --check
```

数据库功能还需要：

```powershell
npm run db:push
npm test
```

## 冲突处理原则

- 不要直接覆盖队友未提交的改动。
- 如果同一页面存在两套实现，先保留队友版本，再手动挑选功能逻辑。
- 数据库字段冲突时，以团队当前 schema 为准，单独迁移新增字段。
- 如果某个功能依赖另一功能，先采用依赖提交。
