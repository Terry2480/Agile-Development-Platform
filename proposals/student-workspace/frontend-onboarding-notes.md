# 前端上手与学生端设计建议

## 文档用途

这是一份独立的调研记录，供队友了解参考项目和选择学生端前端方向使用。

- 不修改队友仓库已有代码。
- 不替换正式首页或 `/projects` 页面。
- 不要求队友采用本文中的全部设计。
- 本文只记录本地运行结果、页面结构和候选设计建议。

## 参考项目已有页面结构

登录页已经表达了平台定位：

```text
学生项目工作台
```

用户可以：

## 建议的学生端信息架构

### 首页

首页回答学生最常用的四个问题：

```text
我有哪些项目？
我今天要做什么？
哪个任务快到期？
最近有哪些资料更新？
```

建议保留：

- 进行中的项目；
- 待办任务；
- 本周截止；
- 项目完成度；
- 最近资料；
- 即将到来的里程碑。

### 项目页

进入某个项目后，使用固定的四个入口：

```text
概览
任务
资料
时间线
```

不要把所有内容都塞进首页，首页负责提醒和汇总，项目页负责具体操作。

### 团队页

团队页优先展示：

- 团队成员；
- 成员角色；
- 邀请码；
- 团队项目；
- 团队标签。

### 个人页

个人页先做：

- 账号信息；
- 我的任务；
- 我参与的项目；
- 登录和退出；
- 个人访问令牌设置。

## 交互设计建议

可以参考 QQ、微信、钉钉的熟悉交互方式，但只借鉴用户习惯，不复制它们的界面和品牌。

建议借鉴：

- 顶部搜索；
- 清晰的导航；
- 成员头像；
- 通知和未读提示；
- 最近活动；
- 快捷入口；
- 移动端底部导航或横向标签。

不建议把 AgileCampus 做成聊天软件。它的主要任务仍然是：

```text
创建项目
拆分任务
安排负责人
记录资料
推进里程碑
查看项目进度
```

## 推荐的第一版学生 MVP

第一版建议只保证以下流程完整：

```text
注册 / 登录
→ 创建或加入团队
→ 创建课程、大创、竞赛或科研项目
→ 添加项目成员
→ 创建任务和里程碑
→ 更新任务状态
→ 创建项目资料
→ 查看项目进度和时间线
```

以下功能建议后置：

- AI 项目助手；
- 飞书登录；
- 飞书提醒；
- 外部 Agent 写入；
- 实时聊天；
- 多人实时协同编辑；
- 复杂审批流程。

## 下一步建议

队友可以按下面顺序继续推进：

1. 先运行 `/demo`，熟悉项目概览、任务、资料和时间线。
2. 再阅读真实的 `/projects`、团队和项目详情代码。
3. 画出学生登录后的主流程。
4. 确定首页、项目页、任务页、资料页的低保真结构。
5. 从一个完整流程开始实现，不要同时铺开所有功能。

推荐的第一个前端任务是：

```text
学生首页：项目汇总 + 待办任务 + 即将到期 + 最近资料
```

这项功能可以独立设计和评审，确认后再接入真实数据库，不会阻塞队友现有的项目详情页面。
